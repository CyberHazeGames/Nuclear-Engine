# Source-observed limitations

Inspected on 2026-09-21. These are bounded observations for navigation and diagnosis, not an exhaustive bug audit or runtime test report. Recheck the source before relying on an entry, and remove/update entries when fixed.

| Area | Observation and consequence | Evidence |
| --- | --- | --- |
| Build toolsets | First-party native solution projects target Visual Studio 2026 / MSVC v145; third-party library naming and prebuilt outputs may still reference older toolsets and need checking when building dependencies. | [Build guide](BuildAndValidation.md), [dependency script](../RunCmakeForDependencies.bat) |
| CMake | Root module-path syntax is malformed, wiring is incomplete, and Samples names `main.cpp` instead of `Main.cpp`. A portable CMake build is not established. | [Root CMake](../CMakeLists.txt), [engine CMake](../Nuclear.Engine/CMakeLists.txt), [Samples CMake](../Samples/CMakeLists.txt) |
| Copy script | Assimp/PhysX/Diligent filenames and paths are hard-coded; final `exit 0` can conceal copy failures. It does not supply every external dependency. | [Copy script](../CopyDependenciesBinaries.bat) |
| Platform support | Nuclear.Platform replaces SDL with a Windows x64 backend and neutral headers. Other platform backends are unimplemented; Windows export declarations, renderer integration, native plugins, and toolchain assumptions still need porting. ImGui secondary native viewports, gamepads, and explicit IME composition positioning are not implemented. | [Platform guide](Platform.md), [NE_Compiler.h](../Nuclear.Engine/include/NE_Compiler.h), [GraphicsModule.cpp](../Nuclear.Engine/Source/Graphics/GraphicsModule.cpp) |
| Tests | A focused Windows platform smoke project exists; there is no general engine test suite or tracked CI workflow. Validate with the solution build and relevant sample behavior. | [Build guide](BuildAndValidation.md#choosing-validation) |
| Networking | Nuclear.Platform supplies Windows UDP/TCP transport and headless loopback tests. Replication, reliable UDP, sessions, message framing, encryption/authentication, and other platform backends are not implemented; LAN/WAN behavior is unverified. | [Networking guide](Networking.md), [Networking.h](../Nuclear.Platform/include/Nuclear.Platform/Networking.h) |
| Profiling | Capture defaults off. GPU queries are asynchronous/optional; runtime validation covers D3D11 only. Explicit allocation tracking covers registered identities rather than all engine allocations; no allocation stacks or hardware temperature/clock counters are collected. System CPU load is unavailable across multiple Windows processor groups. | [Profiling guide](Profiling.md), [GPU queries](../Nuclear.Engine/include/Profiling/GpuQuery.h) |
| Module DLLs | The manager loads external module DLLs before startup and unloads them at shutdown. It does not hot reload, scan arbitrary DLL names, or isolate incompatible C++ binary interfaces. | [ModuleManager.cpp](../Nuclear.Engine/Source/Core/ModuleManager.cpp), [plugin ABI](../Nuclear.Engine/include/Core/EngineModulePlugin.h) |
| Scene persistence | Save/load snapshots list only entity info, light, and mesh components. Other component state is not automatically persisted. | [Scene.cpp](../Nuclear.Engine/Source/Core/Scene.cpp), `SaveScene` / `LoadScene` |
| System order | `Update_All` iterates an unordered map; adding systems in a certain order does not establish update order. | [System.h](../Nuclear.Engine/include/ECS/System.h), [System.cpp](../Nuclear.Engine/Source/ECS/System.cpp) |
| Script component coverage | Only EntityInfo and Light have managed component wrappers and registered add/has operations. Other native component types still need managed APIs. | [ScriptingRegistry.cpp](../Plugins/Scripting.CSharp/Source/ScriptingRegistry.cpp), [managed components](../Nuclear.ScriptCore/Components) |
| Scripting modules | The registry selects one active backend; scripting manifests are not loaded dynamically. C# is registered by engine startup, while Lua is a buildable scaffold with no runtime or registration. The asset manager still uses a callback adapter; the other built-in singleton modules derive directly from `EngineModule`. | [ScriptingModule.cpp](../Nuclear.Engine/Source/Scripting/ScriptingModule.cpp), [EngineModule.h](../Nuclear.Engine/include/Core/EngineModule.h), [Lua scaffold](../Plugins/Scripting.Lua/README.md) |
| Audio plugins | XAudio2 and OpenAL DLLs load by backend name, with no manifest discovery or hot swapping. A solution build does not validate physical audio-device initialization or playback. | [AudioModule.cpp](../Nuclear.Engine/Source/Audio/AudioModule.cpp), [build guide](BuildAndValidation.md#choosing-validation) |
| .NET runtime | Nuclear.Managed selects stable .NET 10 hostfxr from the system installation; the x64 .NET 10 runtime is required. Custom DOTNET_ROOT installations are not discovered. CoreCLR stays loaded until process exit. | [Build guide](BuildAndValidation.md), [CSharpScriptingBackend.cpp](../Plugins/Scripting.CSharp/Source/CSharpScriptingBackend.cpp) |
| Sample prerequisites | Models, textures, imported assets, and runtime outputs are substantially ignored/local. The LearnOpenGL content subset does not supply all models used by Sample1 and the selector. Check exact paths before diagnosing runtime behavior. | [.gitignore](../.gitignore), [content setup](BuildAndValidation.md#learnopengl-sample-content) |
| Editor authoring | Retained UI supports document tabs, dock groups and independent native panels. Projects/scenes/layouts are session data: disk project/layout persistence, undo/redo and play mode are not implemented. Asset tabs expose resource details, with no shader/material authoring. Native tear-off has been run on D3D11; OpenGL tear-off is unavailable. Physics/audio/script components remain authoring data. | [Editor.md](Editor.md), [Editor startup](../Nuclear.Editor/source/Nuclear.Editor.cpp) |

The initial guide-writing pass did not build or launch the engine. Subsequent Debug x64 build and sample startup validation, including remaining sample-content and rendering warnings, is recorded in the [build guide](BuildAndValidation.md#running-samples).
